## 2. Logic Chain

1. **Premise**: Requirement R2 mandates a responsive HTML5 `<video>` player powered by `hls.js` with fallback to native Safari HLS, dual-mode fallback to sanitized iframes, 10-foot Android TV D-pad remote navigation (seek ±10s with visible indicator, center play/pause, up/down audio & subtitle drawer, back without focus traps), and mobile touch gestures (double-tap seek, vertical swipes for volume/brightness, aspect ratio toggle, native PiP, AirPlay).
2. **Current Player Limitation (from 1.1)**: `UnifiedVideoPlayer.tsx` is exclusively an iframe container. Because an iframe embeds third-party cross-origin content, the parent JavaScript runtime has no programmatic access to:
   - The underlying `<video>` element,
   - `currentTime`, `duration`, `playbackRate`, `volume`, or `muted`,
   - Video frame dimensions or aspect ratio,
   - Audio tracks or subtitle cue tracks.
3. **Remote Control Failure (from 1.2)**: 
   - Because `UnifiedVideoPlayer.tsx` lacks programmatic video control, D-Pad Left/Right seek (±10s) and Center Play/Pause cannot be executed on the iframe.
   - Furthermore, `tvNavigation.ts` currently treats arrow presses as DOM focus movements across surrounding buttons rather than media seek commands.
   - When an iframe takes focus, the browser traps keyboard events within the foreign frame. The Android TV remote is rendered inoperable.
4. **Touch Gestures Failure (from 1.3)**: 
   - No touch listeners exist. Furthermore, touch events dispatched inside an iframe are swallowed by the cross-origin frame and cannot be detected by parent React touch listeners.
   - A direct HTML5 `<video>` layer with an overlay gesture HUD is required to capture double-tap, vertical swipes, and aspect ratio adjustments.
5. **Subtitle and Audio Track Inaccessibility (from 1.4)**: 
   - Subtitle rendering and audio track switching require direct manipulation of `hls.subtitleTracks`, `hls.audioTracks`, or HTML `<track>` elements with custom CSS WebVTT cue overlays. These are impossible within cross-origin embed iframes.
6. **Watch Progress and Exact-Second Resume Failure (from 1.5)**: 
   - `watchHistoryService.ts` lacks `currentTime` and `duration` fields for video media, and `UnifiedVideoPlayer.tsx` cannot read time from iframes. Without direct `<video>` access, exact-second resume cannot function.
7. **Build Cleanliness (from 1.6)**: 
   - 25 TypeScript errors prevent `npm run build` from succeeding, violating Acceptance Criterion 4.1.

## 3. Caveats

1. **Direct Stream Extractor Dependency (Requirement R1)**:
   - The Cinema Player's direct HTML5 `<video>` engine depends on receiving valid direct HLS (`.m3u8`) URLs, multi-track audio descriptors, and `.vtt` subtitles from the resolver endpoint being investigated by Survey Explorer 1.
   - The player must implement an architecture that attempts direct stream playback first, and seamlessly falls back to the existing sanitized iframe embed system if direct resolution fails or returns an error.
2. **Capacitor Android TV Key Event Passing**:
   - In Android TV WebView environments, certain D-Pad keys (such as KEYCODE_DPAD_CENTER / 23 and KEYCODE_BACK / 4) can be captured by the Android View hierarchy before reaching the web document unless handled in `keydown` with `event.preventDefault()` or passed via Capacitor bridge.
3. **Cross-Origin Video & CORS Headers**:
   - For `hls.js` to parse `.m3u8` manifests and `.ts`/`.m4s` chunks in the browser, the video streams must either have permissive CORS headers (`Access-Control-Allow-Origin: *`) or be proxied through the local Express proxy backend (`/api/stream-proxy`).

## 4. Conclusion & Architecture Recommendation

### 4.1 Architecture Assessment
`UnifiedVideoPlayer.tsx` must be refactored into a **Dual-Mode Cinema Video Player**:
1. **Mode A: Direct HLS Cinema Player (Primary)**:
   - Responsive HTML5 `<video>` element managed via a custom React hook (`useHlsPlayer`).
   - `hls.js` initialization with low-latency configuration, audio track switching (`hls.audioTracks`), and subtitle track switching.
   - Native Safari HLS fallback (`video.canPlayType('application/vnd.apple.mpegurl')`).
   - Custom Cinema HUD overlay that floats *above* the video.
2. **Mode B: Sanitized Iframe Embed (Fallback)**:
   - Preserves existing multi-server failover (`vidlink.pro`, `vidsrc.to`, etc.) when direct HLS extraction fails or stream errors out.
   - Wrapped with an invisible focus guard overlay to prevent remote focus trapping inside foreign frames.

### 4.2 Required Component Hierarchy
```
src/components/Player/
├── CinemaPlayer.tsx             # Master Dual-Mode Player (Direct HLS + Iframe Fallback)
├── CinemaHUD.tsx                # 10-Foot TV & Mobile HUD (Controls, Scrubber, Badges)
├── GestureOverlay.tsx           # Mobile Touch Zones (Double-tap seek, Volume/Brightness swipe)
├── TrackDrawer.tsx              # D-Pad Up/Down Accessible Drawer (Subtitles & Audio Tracks)
├── SeekIndicator.tsx            # Animated Visual Seek Bubble (<< -10s / >> +10s)
├── BrightnessVolumeOverlay.tsx  # Vertical HUD meters for swipe gesture feedback
└── hooks/
    ├── useHlsPlayer.ts          # hls.js lifecycle, Safari fallback, quality/audio/subtitle tracks
    ├── usePlayerGestures.ts     # Touch gesture coordinator (double-tap, vertical swipes)
    ├── useTVRemoteNavigation.ts # D-Pad Left/Right seek, Center Play/Pause, Up/Down Drawer, Back
    └── useWatchProgress.ts      # 5s interval progress persistence & exact-second resume
```

### 4.3 Detailed Specification of Missing Features for Implementation

| Feature | Requirement | Recommended Implementation |
|---|---|---|
| **Direct HLS & Safari Fallback** | R2 | Use `hls.js` when `Hls.isSupported()`; fall back to `video.src = m3u8Url` for Safari / iOS. |
| **D-Pad Left/Right Seek** | R2 | Intercept `ArrowLeft` (37/21) & `ArrowRight` (39/22) on window when player is open; seek `video.currentTime ± 10` with `preventDefault()`. |
| **Seek Time Indicator** | R2 | Render `<SeekIndicator delta={±10} timestamp={targetTime} />` that pulses for 800ms upon seek. |
| **D-Pad Center Play/Pause** | R2 | Intercept `Enter` (13/66) & `KEYCODE_DPAD_CENTER` (23); toggle `video.paused ? video.play() : video.pause()`. |
| **D-Pad Up/Down Drawer** | R2 | Intercept `ArrowUp` (38/19) & `ArrowDown` (40/20); toggle `<TrackDrawer isOpen={true} />`. |
| **Iframe Focus Trap Prevention** | R2 | When in Iframe Fallback mode, place an invisible transparent overlay or intercept `focus` on the iframe, returning focus to HUD controls. |
| **Back to Exit** | R2 | Intercept `Escape` / `KEYCODE_BACK` (4); if Drawer is open, close Drawer; else close Player. |
| **Mobile Double-Tap Seek** | R2 | Detect 2 taps within 300ms. If `clientX < width/2`, seek -10s; if `clientX > width/2`, seek +10s. Trigger ripple animation. |
| **Right Vertical Swipe Volume** | R2 | Track `touchmove` delta on right 50% screen; update `video.volume = clamp(volume + delta, 0, 1)`. Display vertical bar HUD. |
| **Left Vertical Swipe Brightness**| R2 | Track `touchmove` delta on left 50% screen; update overlay opacity `(1 - brightness)`. Display brightness bar HUD. |
| **Aspect Ratio Toggle** | R2 | Toggle CSS `object-fit: contain` (Original) / `cover` (Zoom) / `fill` (Stretch). |
| **Picture-in-Picture** | R2 | Call `video.requestPictureInPicture()` if `document.pictureInPictureEnabled`. |
| **AirPlay** | R2 | Call `(video as any).webkitShowPlaybackTargetPicker()` on WebKit platforms. |
| **Subtitles & Audio Drawer** | R2 | Render accessible slide-out drawer with radio lists for Subtitle language (`.vtt`) and Audio track (`hls.audioTracks`). |
